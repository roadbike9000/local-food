- (note) Why: local-food lets vendors self-serve their storefront but has no platform-admin layer and only a manual isAvailable toggle. Pain to solve (no admin lifecycle mgmt) + vision to realize (real numeric inventory instead of hand-tracking).
- (capability) CAP-1 (FR-1): intent - Customer can remove a line item from their cart. success - line drops immediately, total recalculates to remaining lines only. Already implemented; ships as verification, not new work.
- (capability) CAP-2 (FR-2): intent - System restricts admin capabilities to users holding the Admin role. success - non-admin hitting an admin route/action is denied; admin actions attributable to the acting admin.
- (capability) CAP-3 (FR-3): intent - Admin can onboard a new vendor onto the platform. success - new vendor gets a live storefront at /vendors/{slug}; slug collisions rejected with a friendly error, not a raw DB failure.
- (capability) CAP-4 (FR-4): intent - Admin can deactivate a vendor (soft-delete). success - deactivated vendor's storefront shows unavailable message, no new orders placeable, existing in-flight orders keep fulfilling, vendor data not deleted.
- (capability) CAP-5 (FR-6): intent - Customer sees a clear out-of-stock indicator on any zero-stock product. success - badge renders everywhere the product displays, matches current stock, no stale in-stock display.
- (capability) CAP-6 (FR-7): intent - Out-of-stock products cannot be added to cart or checked out. success - add-to-cart disabled client-side; checkout re-validates per-line stock sufficiency server-side, rejects shortfall orders.
- (capability) CAP-7 (FR-8): intent - Inventory updates immediately after a sale completes. success - stock decrements on payment confirmation not session creation; never negative; last-unit race resolves to exactly one winner.
- (capability) CAP-8 (FR-9): intent - Admin can view current stock levels across all vendors on demand. success - dashboard reflects live stock at request time, flags low/out-of-stock items, reachable only to Admin.
- (capability) CAP-9 (FR-10): intent - Admin gets an SMS alert when a product's stock crosses its low-stock threshold. success - alert fires once per crossing event, no repeat spam; a failed send is never recorded as delivered.
- (capability) CAP-10 (FR-11): intent - Customer can adjust a cart line's quantity in place via a stepper. success - quantity steps between 1 and available stock, total recalculates immediately, no remove-and-re-add needed.
- (capability) CAP-11 (FR-12): intent - Stock Quantity is captured at product creation and backfilled for existing products. success - no product exists without a stock quantity going forward; every pre-existing product has a defined value after migration.
- (constraint) Admin identity resolved solely via new Admin table (clerkUserId), never a Clerk session claim -- ARCHITECTURE-SPINE.md AD-1.
- (constraint) Product.isAvailable is dropped; availability/sufficiency computed at read time only, no cached/derived boolean under any name -- AD-2.
- (constraint) All Stock Quantity writes go through one adjustStock() function, conditional update, transactional across multi-item orders -- AD-3.
- (constraint) Vendor-deactivated checked through one shared guard, assertVendorActive(), which throws rather than returns -- AD-4.
- (constraint) Admin attribution is a plain FK field (deletedByAdminId etc.), not an audit-log table -- AD-5.
- (constraint) Admin pages live under /admin/*, gated by getCurrentAdmin() in addition to middleware auth -- AD-6.
- (constraint) Vendor slug collisions checked via resolveVendorSlug(), admin-create path only -- AD-7.
