## What Went Well

- **The token foundation (8.1) held for the whole epic.** Every later story referenced named `DESIGN.md` tokens instead of ad-hoc values, and the "canonical token over mock's drifted pixel" precedent set in 8.1 was applied consistently through 8.5 with zero exceptions.
- **A real security bug was caught and fixed same-session, not just a cosmetic nit, despite this being a "visual-only" epic.** Story 8.3's hero background interpolated an unescaped, DB-derived `imageUrl` into an inline CSS `url()` — a CSS-injection/clickjacking vector if a vendor ever hand-crafted a product's image URL. Fixed by switching to `next/image`, which removes the injection sink entirely rather than attempting to escape around it.
- **A self-inflicted ARIA-spec violation was caught by the same review round that introduced it.** Story 8.4 paired `role="alert"` with an explicit `aria-live="polite"` on all 3 new dynamic messages — the explicit value silently overrides the implicit assertive one, defeating the exact accessibility feature the AC asked for. No gap between introduction and detection reaching a real user.
- **Deferred-work.md's predict-and-check discipline paid off twice, in both directions.** 8.4's review predicted checkout-success (8.5) would duplicate `button-pill-primary`'s hand-typed Tailwind string — it did, confirmed by 8.5's own review. 8.3's review predicted 8.4 would duplicate `caption-plate`/`pickup-banner` — it didn't, since cart's pickup-time UI turned out to be a different shape (form fieldset, not a banner). Both predictions were checked against reality rather than left to rot, and both closed the loop explicitly.
- **ATDD scoping made deliberate, documented no-test decisions instead of silently skipping or force-authoring fragile ones.** 8.4's 3 untestable `role="alert"` paths and 8.5's pure-restyle both got an explicit rationale in their ATDD checklists.
- **Full regression run twice per story (project convention) never found a real regression this epic** — only the project's own pre-existing parallel-execution flake class (a different test fails each run, always passes in isolation), re-confirmed 3 separate times (8.3, 8.5×2).

## What Slowed Us Down / Recurring Problems

- **The `/code-review` orchestrator's own consolidation pass died silently twice this epic** (8.3 and 8.4 reviews) — confirmed via `ListAgents` showing nothing running. Both times required manually triaging the 10 raw finder-agent reports instead of getting an automatic consolidated report. This is now a proven, repeatable fallback rather than a one-off surprise, but it's a real tooling reliability gap worth expecting again, not a process failure.
- **8.1's ESLint radius-token rule needed a follow-up fix** (variant-prefix matching, non-literal className expressions) — caught in a round-2 review, not round 1. Minor, but the only story this epic that needed two review rounds.

## Key Insights

1. **"Visual-only" doesn't mean "review-light."** A pure restyle epic still surfaced a real security bug (CSS injection) and a real accessibility regression (ARIA conflict) — both came from touching real data flow (an image URL) and real semantics (ARIA roles), not from anything cosmetic.
2. **A deferred finding's forward-risk prediction is worth checking against the very next story's diff, not just logging and forgetting.** Confirmed one prediction, refuted the other — cheap to verify, actionable either way.
3. **Manual finder-agent triage should be treated as `/code-review`'s expected fallback path**, not an exception — it's now failed to auto-consolidate on 2 of 5 stories this epic alone.
