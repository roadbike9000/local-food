## What Went Well

- **One review round found and fixed 11 real issues without needing a second round.** Heaviest single-round patch count of any epic so far, and every one of them landed clean — no round-2 needed, no follow-up regressions from the patches themselves.
- **The write-side validation gap (`isValidTimeZone()` vs. the UI's actual `<select>` option list) was caught before it could strand a vendor with an unselectable value.** `isValidTimeZone("UTC")`/`"US/Eastern"`/`"EST5EDT"`/etc. all passed the original schema check but don't appear in `Intl.supportedValuesOf("timeZone")`, the exact list both forms render from. Verified by direct execution (`node -e`), not inspection — same discipline Epic 6's retro named as worth keeping. Fixed with a new `isSelectableTimeZone()` scoped to the two write-path schemas only.
- **The stale-Clerk-session bug (bare `request.newContext()` losing live session refresh late in a long full-suite run) was diagnosed once during dev-story, then found and fixed 3 more times during code review** — once in the story's own new spec file (which had reintroduced the exact anti-pattern just fixed elsewhere in the same PR), then twice more as a deliberate cross-file sweep of pre-existing sibling spec files. A real bug class, caught at its root and then swept for recurrence rather than patched once and left.
- **A live product decision (confirm-gate before saving a timezone change on a vendor with existing pickup slots) got resolved same-session, not deferred to a future epic** — matches the standing rule from Epic 5's retro (surface a reviewer-flagged consequential item immediately). Implemented as a `window.confirm()` gate, same shape as `DeactivateVendorButton`'s existing precedent.
- **The doc-heading-not-line-number rule held with zero drift** — first epic since that rule was adopted (Epic 6's retro, 4th time carried) where it actually stuck through a full story cycle.
- **All 5 deferred findings from round 1 were resolved in a deliberate follow-up pass** (not left to rot in `deferred-work.md`) — including a hydration-mismatch-risk fix (server-computed timezone list passed as a prop instead of two independent client-side `Intl.supportedValuesOf()` calls), a debounce fix for a keyboard-arrow-key PATCH storm, and a test-locator hardening (scope by `vendor.slug` not `vendor.name`).

## What Slowed Us Down / Recurring Problems

- **Nothing novel this epic.** The one recurring issue (stale Clerk session in bare `request` fixtures) is a known, already-documented class from Epic 6 — this epic's contribution was finding 3 more latent instances of it, not discovering a new failure mode.

## Key Insights

1. **A single-story epic can still surface a heavy review round** — story size and review-finding count aren't well correlated when the story touches an existing validation surface (`isValidTimeZone()`) with a broader/narrower mismatch baked in from a prior epic. Worth remembering when estimating review effort from story scope alone.
2. **Sweeping a newly-diagnosed bug class across sibling files (not just the file that surfaced it) paid off again** — same pattern Epic 4's retro named ("a review finding's fix is new code, needs the same regression discipline"), now demonstrated on a test-infrastructure bug instead of application logic.
