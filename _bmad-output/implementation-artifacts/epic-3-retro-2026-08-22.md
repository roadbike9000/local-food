## What Went Well

- **One-round closure held for a second epic straight.** 5 consecutive stories (2.1–2.3, 3.1–3.2) have now each stabilized on the first review pass.
- **Story 3.2 sidestepped the admin e2e credential gap entirely by design** — nothing in it sits behind `getCurrentAdmin()`'s route gate (webhook is server-to-server, `decrementStock()`/`setStock()` are called directly in tests). Result: 100% of Story 3.2's new test coverage ran for real, the first story since Epic 2 began where that's true. This is a genuine de-risking move, not luck — the story's own Dev Notes called it out explicitly as "a break from the pattern every Epic 2/3.1 story had to work around."
- **Epic 2's retro lessons were applied proactively in Story 3.1, not just caught in review.** The accessible-badge pattern, the `take: 100` pagination cap, and the ATDD activation-script fix were all built into the implementation from the start (Dev Notes cite the Epic 2 retro by name for each). Zero activation-script mistakes across both stories.
- **Independent triple-convergence plus live verification became this epic's standout technique.** All three review layers (Blind Hunter, Edge Case Hunter, Acceptance Auditor) independently found Story 3.2's shortfall-rollback bug before any triage — the first time this session all three agreed on the same top finding cold. The fix was then proven, not just asserted: reverted, re-ran the regression test, watched it fail with the exact predicted symptom, restored, watched it pass.
- **Two real infrastructure bugs were found and fixed during implementation itself**, not surfaced by review: the mock SMS provider's message log wasn't actually shared across Next.js route handlers in dev mode, and `fullyParallel` required both serial ordering and unique per-fixture product names to isolate admin fan-out assertions. Both were root-caused with direct evidence (instrumentation, "Received array" contents) rather than guessed at.

## What Slowed Us Down / Recurring Problems

**1. The admin e2e credential gap is now three epics old and still unresolved.** Story 3.1's 3 admin-authenticated tests skip for the same reason Epic 2's did — `E2E_ADMIN_EMAIL`/`E2E_ADMIN_CLERK_ID` were never provisioned. Epic 2's retro named this the single largest carried-forward risk into Epic 3; Epic 3 confirmed the prediction on its very first story. Story 3.2 avoided the gap by design, but that's a workaround for one story's shape, not a fix.

**2. The `requireAdmin()` fail-closed decision — named as Epic 3.2's exact trigger condition — was never revisited before 3.2 shipped.** Epic 2's retro action item 6 said explicitly: decide before Story 3.2 ships an SMS-triggering path, because that's the first admin action with a real external side effect. Story 3.2 shipped that exact path without the decision ever coming back up. Nothing broke as a result (the gate held), but the decision point was skipped rather than answered.

**3. Doc drift recurred in both stories' reviews — a third epic in a row.** Story 3.1's review found a misattribution (`isInStock()` credited to the wrong story); Story 3.2's found incorrect test-count arithmetic and an `api-contracts.md` section left stale after an execution-order fix. Epic 2's retro action item 4 (a doc-accuracy self-check before requesting review) didn't stop this from recurring — both stories' Dev Notes were scoped carefully, but scoping accuracy and content accuracy turned out to be different problems.

**4. A new shape of atomicity bug shipped despite the "check-then-act" lesson being named twice already.** Story 3.2's cross-order race on `lowStockAlerted` wasn't a classic check-then-act sequence — it was a correct-for-one-order design (`crossedLowStock` computed inside an already-guarded transaction) that didn't account for *two different orders* racing the same product. Epic 2's retro action item 5 named check-then-act specifically; this bug shows the underlying lesson ("will this invariant hold under two concurrent instances of the same code path, not just one") is still being caught by review, not applied at implementation time, even when the surface shape of the bug isn't the one already named.

**5. `npm run test:unit` still isn't a CI step.** Open since Story 1.2's round-2 review — now three epics old.

## Key Insights

1. **Sidestepping a known blocker by design beats waiting on it.** Story 3.2 made real, fully-verified progress despite the admin credential gap staying open, by shaping the story so it never depended on the gate at all. Story 3.1, which did depend on it, hit the gap exactly as predicted. Where a story's shape allows it, avoiding a known external dependency is more reliable than hoping the dependency gets resolved in time.
2. **Concrete, mechanical lessons transfer at implementation time; judgment-call lessons don't, without a deliberate stop.** The accessibility pattern, the pagination cap, and the ATDD script fix are all "do X the same way every time" — and all three were applied proactively in Story 3.1 with no review reminder needed. The `requireAdmin()` decision and the cross-order atomicity question are both "notice a new situation and reason about it" — and both slipped past implementation despite being named in the prior retro. A retro action item that says "decide before story X" needs to actually gate story X's start, not just be logged and trusted to surface itself.
3. **Independent multi-layer review convergence, followed by live fix verification (revert, reproduce failure, restore), is the highest-confidence bug-catching technique demonstrated this session.** Worth treating as the standard for any finding on a payment-critical or side-effect-triggering path, not a one-off applied only because three reviewers happened to agree.
